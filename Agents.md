# Инструкции для AI-агентов

## Проект

Fear — Python 3.14+ Telegram client на Kurigram/Pyrogram-совместимом API. Точка запуска — `main.py`; настройки находятся в `config.py`; клиент и загрузчик — в `src/core/`; встроенный `System` и устанавливаемые модули — в `modules/`. SDK `fear-module` ведётся отдельно в соседнем репозитории.

## Работа с кодом

- Сохраняйте совместимость публичного SDK Fear Module и сверяйте изменения с `/home/keva1z/Projects/fear-module` (если репозиторий доступен). Не копируйте SDK внутрь Fear.
- Все команды управления Fear (включая FUR `.flist`, `.fins`, `.frem`, `.fupd`) должны объявляться и регистрироваться в `modules/system/main.py`. Сервисы реализации можно держать в `src/core/`.
- Модули из `modules/<id>/main.py` и их зависимости исполняются с правами процесса Fear. FUR-пакеты проверяются по SHA-256 каталога; это не песочница и не подпись издателя. Не ослабляйте проверку архива/ID и не загружайте произвольные URL или pip-спецификаторы.
- Не размещайте временные или резервные каталоги с `main.py` в видимой загрузчику области `modules/`; используйте имена с ведущей точкой и исключайте их из загрузки.
- В клиенте два Telegram-сеанса: пользовательский и бот. Учитывайте их разные `ClientType`, обработчики, порядок запуска/остановки и то, что `SECRETARY`-обработчики подключаются к боту.
- Не печатайте значения секретов, токены, содержимое `.env` или данные файлов `.session`. Сессионные файлы дают доступ к аккаунту.
- Логи приложения настраиваются через `LOG_LEVEL`; не выводите API secrets, токены или содержимое сессий.
- Сохраняйте `uv.lock` согласованным с `pyproject.toml`; Git URL-зависимости должны быть закреплены lock-файлом.
- При добавлении параметров конфигурации обновляйте `.env.example` и проверяйте, что параметр действительно читается кодом.
- FUR-установка проходит в два этапа: подготовка файлов, затем загрузка через `FearClient.load_modules()`. Сохраняйте возможность отката каталога и записи `.data/fur-installed.json`, если загрузка модуля завершается ошибкой.
- Сторонние библиотеки ставятся отдельно в `.data/module-deps/<id>/`; Python-модули разделяют `sys.modules`, поэтому несовместимые версии зависимостей конфликтуют и удаление файлов не выгружает уже импортированный код.
- Не меняйте `uv.lock` или уже имеющиеся пользовательские изменения без необходимости. Перед правкой проверьте `git status`.

## Проверки

- Синтаксис: `python -m compileall -q main.py config.py src`
- Lock-файл: `uv lock --check`
- Unit-тесты: `uv run --locked python -m unittest discover -s tests -v`
- Типы: `ty check`
- Для сетевых сценариев (авторизация, BotFather, настройка бота) нужны отдельные изолированные тесты; не запускайте их против реального Telegram-аккаунта без явного запроса.
- В репозитории пока нет настроенного линтера или CI. Не утверждайте, что поведение проверено тестами, если запускали только компиляцию.
