# Формат модулей Fear и установка из Telegram

Это предложение для следующей версии SDK и будущих Telegram-команд установки. Сам менеджер пока не реализуется. Сейчас Fear ищет `src/modules/<каталог>/main.py`, импортирует его в основном процессе и вызывает `FearModule.register()`.

## Формат модуля

Использовать обычный каталог с дескриптором `fear-module.toml`, Python-точкой входа и lock-файлом зависимостей:

```text
modules/                         # каталог исходников; сюда ставится модуль
└── org.example.greetings/
    ├── fear-module.toml
    └── module.py

.data/module-deps/               # сюда отдельно ставятся Python-зависимости
└── org.example.greetings/
    └── 1.2.0/
```

Пакетные файлы зависимостей нельзя раскладывать прямо в `modules/`: загрузчик перебирает каталоги модулей и ожидает в каждом entrypoint, а библиотеки могут содержать совпадающие имена и не являются модулями Fear. `modules/` содержит только код и метаданные расширения; `.data/module-deps/` содержит установленное окружение зависимостей.

```text
org.example.greetings/
├── fear-module.toml
├── module.py
└── requirements.lock       # либо вложенный в архив lock-файл
```

Пакет модуля:

```text
greetings-module.zip
├── fear-module.toml
├── module.py
└── requirements.lock
```

Пример манифеста:

```toml
[module]
id = "org.example.greetings"
version = "1.2.0"
name = "Greetings"
entrypoint = "module:GreetingsModule"
sdk = ">=0.2,<0.3"
python = ">=3.14,<3.15"

[permissions]
telegram_user = false
telegram_bot = true
filesystem = "module-data"
network = true
```

`id` — постоянный уникальный идентификатор, каталог не зависит от отображаемого имени. Версии следуют SemVer. `entrypoint` обозначает класс-наследник `FearModule`; хуки SDK: создание экземпляра с host context, `register()`, затем `unregister()` и необязательные `on_start()`/`on_stop()`. Хуки должны быть идемпотентны, `unregister()` снимает обработчики и закрывает ресурсы.

SDK следует расширить типизированным host context, интерфейсами user/bot API и `ModuleMetadata`; модуль не должен создавать Telegram-клиенты. Нужны типизированный `ModuleError`, регистрация обработчиков с дескрипторами снятия, версия контракта и проверка манифеста. Текущий `FearModule` можно поддержать адаптером до следующего major release.

## Как будет работать команда установки

Команда `.fins <name>` разрешает короткое имя через каталог доступных модулей, получает архив и закреплённые метаданные, а затем выполняет установку. Впоследствии каталог может выдавать официальный пакет, версию, хеши и подпись. Не следует трактовать `<name>` как произвольный URL или pip specifier.

Предлагаемый поток:

1. Проверить, что команду отправил владелец user-клиента (`filters.me`) или явно разрешённый администратор. Проверять имя, версию, совместимость Fear/SDK/Python и размер архива.
2. Скачать архив во временный каталог, проверить путь файлов внутри архива (защита от `../`), хеш/подпись и схему манифеста.
3. Подготовить зависимости вне event loop как отдельный процесс. Разрешённые wheel-файлы установить через `uv pip install --target <deps-staging> --require-hashes -r requirements.lock`. Это не изменяет `.venv` Fear и не требует перезапуска Python-процесса.
4. Валидационным subprocess с путём зависимостей импортировать entrypoint и проверить версию SDK и наличие ожидаемого класса. Он не заменяет песочницу, но позволяет обнаружить синтаксические и простые ошибки до активации.
5. Атомарно переместить подготовленные файлы в `modules/<id>` и `.data/module-deps/<id>/<version>`, записать состояние установки, затем попросить хост загрузить модуль.
6. Хост добавляет dependency path в `sys.path` **до импорта** модуля, вызывает `importlib.invalidate_caches()`, импортирует entrypoint, создаёт модуль и вызывает `register()`. Ошибка активации откатывает файлы/состояние и оставляет прежний набор обработчиков.
7. Ответить в Telegram результатом и логом ошибки без секретов. Установка не должна выполнять pip внутри обработчика и блокировать asyncio loop.

Имя в `.fins` разрешается только через доверенный каталог пакетов. Если каталог появится позже, установщик сначала можно сделать без него: получать архив из заранее заданного репозитория, но с той же схемой манифеста, проверкой хеша и allowlist источников. Это ещё не полноценный пакетный менеджер.

## Можно ли ставить сторонние библиотеки без перезапуска Fear?

Да. Python не требует перезапуска процесса, чтобы импортировать ранее не загруженный пакет. Установщик ставит библиотеку в отдельный каталог модуля через `--target`, а хост добавляет его в `sys.path` до импорта entrypoint и обновляет import cache. Установка при этом не меняет системное окружение и виртуальное окружение Fear. `.reload` в текущей реализации останавливает и запускает Telegram-клиенты заново, но сам процесс Fear остаётся жив.

Однако отдельный каталог файлов не даёт полной изоляции библиотек:

- Все загруженные модули делят `sys.modules`. Если два модуля требуют разные версии библиотеки с одинаковым Python import name, одна версия затенит другую. Для первой версии установщика нужно собрать dependency graph и отказать при конфликте.
- Установленная, но ещё не импортированная библиотека обычно доступна сразу. Уже импортированную версию нельзя надёжно выгрузить из текущего процесса. Обновление или удаление активной зависимости, особенно бинарного расширения, потребует перезапуска процесса либо изоляции модуля.
- Порядок путей в `sys.path` влияет на то, какая зависимость победит. Нужны проверка конфликтов и deterministic path order; нельзя просто добавлять все каталоги в начало без учёта зависимостей.
- Код модуля выполняется с правами процесса Fear. Манифестные `permissions` сами по себе не ограничивают доступ; принимать следует только доверенные пакеты, проверять авторизацию команды, подпись/хеш и источник.

Для несовместимых версий библиотек следующий архитектурный этап — отдельный worker-процесс и venv на модуль. Fear передаёт worker-у нормализованные события через IPC, а worker возвращает ограниченные команды host API; объекты Kurigram напрямую сериализовать нельзя. Тогда обновление библиотеки перезапускает только worker модуля, не весь Fear.

## Текущее положение и проверки

Сейчас модульный загрузчик жёстко ищет `src/modules/*/main.py`; `.fins`, манифест, скачивание архивов, установка зависимостей и динамическое добавление путей **не реализованы**. Для будущей реализации загрузчик нужно перевести на один канонический `modules/` каталог и entrypoint из манифеста. Новый пакет должен проходить тесты на конфликт зависимостей, неверный архив/путь, несовместимый SDK, неудачный import/register и откат активного набора.

Не запускать pip/uv напрямую в сообщении/handler-коллбэке. Не размещать архив перед проверкой в каталоге, который автоматически импортируется.
