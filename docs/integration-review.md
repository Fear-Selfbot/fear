# Интеграционное ревью Fear и Fear Module

## Связь проектов

Fear объявляет Git-зависимость на Fear Module в `pyproject.toml` и фиксирует используемый SDK-коммит в `uv.lock`. Fear импортирует `ClientType`/`FearModule`, создаёт экземпляры подклассов из `modules/*/main.py` (и временно поддерживает старый путь `src/modules/*/main.py`), вызывает `register()` и назначает обработчики клиентам по типу. SDK предоставляет типы и хранение обработчиков; фактический жизненный цикл реализует Fear.

## Общая оценка

Публичный контракт используется согласованно: системный модуль передаёт host-клиент в конструктор и использует `add_commands()` и `Command.add_handler()`. `FearClientProtocol` импортируется из `fear_module.protocols`, чтобы работать с текущим зафиксированным Git-коммитом SDK; протокол также экспортируется публично в рабочей копии SDK. Строка зависимости Fear остаётся закреплённой на коммите `321e0ae...`; обновить её следует после публикации/коммита нового SDK API.

Главные оставшиеся риски интеграции: отдельные тесты SDK и Fear не образуют полного контрактного набора; загрузка плагинов исполняет доверенный код прямо в процессе, а библиотечные зависимости используют общий `sys.modules`. Fear сохраняет прежний набор обработчиков при ошибке регистрации.
